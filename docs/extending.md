# Extending the client

All hand-written code lives in `mawaqit/_async`. The sync client
(`mawaqit/_sync`) and the pydantic models (`mawaqit/_generated`) are generated by
`python scripts/generate.py` and are gitignored — never edit them by hand.

## Add a Resource or an operation

1. Add the method to the relevant resource class in `mawaqit/_async/v2.py` or
   `mawaqit/_async/v3.py` — or add a new `SomethingResource` class and expose it
   on the version namespace (`AsyncV2` / `AsyncV3`). Keep it thin:

    ```python
    async def weather(self, uuid: str) -> models.Weather:
        response = await self._client._request("GET", f"2.0/mosque/{uuid}/weather")
        return models.Weather.model_validate(response.json())
    ```

2. Regenerate the sync mirror:

    ```bash
    python scripts/generate.py
    ```

3. Record the operation in the contract test (`IMPLEMENTED` in
   `tests/test_contract.py`) and add a respx test in
   `tests/test_resources_async.py`.

## Add a new API version (e.g. v4)

Versions are additive — no existing code is rewritten.

1. Add the spec at `swagger/4.0.yml` and register it in
   `scripts/generate.py`:

    ```python
    VERSIONS = {"2.0": "v2", "3.0": "v3", "4.0": "v4"}
    SYNC_REPLACEMENTS = {..., "AsyncV4": "SyncV4"}
    ```

2. Create `mawaqit/_async/v4.py` with an `AsyncV4` namespace (model it on
   `v3.py`).

3. Expose it on the client (`mawaqit/_async/client.py`):

    ```python
    @property
    def v4(self) -> AsyncV4:
        if self._v4 is None:
            self._v4 = AsyncV4(self)
        return self._v4
    ```

4. Regenerate, then extend `IMPLEMENTED` and the tests.

## Regeneration in CI

`scripts/generate.py` runs in the Hatch build hook, in the test/lint CI jobs, in
pre-commit, and in the `repository_dispatch`-triggered workflow the backend fires
on an API release. The contract tests fail if a regenerated spec drifts from the
resources.
